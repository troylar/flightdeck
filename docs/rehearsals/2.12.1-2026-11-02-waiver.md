# Two-computer rehearsal waived (not rehearsed): Flightdeck 2.12.1

- Version: 2.12.1
- Date: 2026-11-02
- Decision: the project owner waived the two-computer rehearsal (docs/rehearsals/README.md, *The release gate*) for this release.

## Why it was asked for

2.12.1 is a patch, so the gate doesn't require a rehearsal. The run and notes formats aren't touched, `src/storage/` changes only by one new read path in `repo.js` (below), and `mutateRun`, `canReplace`, `recover`, `applyRunRead`, `useFs`, `acceptProposal` and `queued` are byte for byte as in 2.12.0. It does ship a new `AGENTS.md` and a new file in the team folder, `.flightdeck/skills/_flightdeck/file-formats.md`, written by the existing writers, `flightdeck install` and Settings > AI assistant files, with the same rules and record. Copy instructions and Download skills ZIP write nothing to any folder. It also changes how a record from a newer version and an old copy left by an older app are read (below), and `src/storage/repo.js` gains one read path, `readRaw`, which reads a file's bytes through the existing `blob()` so a byte-order mark is kept: Folder health's scan reads the files for AI assistants and their waiting copies with it, and Settings reads them with it for `PF.contract.classifyCopies`. `src/storage/fs.js` doesn't change. Nothing new removes or archives a file: an old copy is only named, with its path, as safe to delete by hand.

## What the rehearsal would have covered

On a test folder, with one computer on 2.12.0 and the other on 2.12.1:

- Update on one computer, then the other computer seeing the new `AGENTS.md`, the file formats, the record and Folder health's result.
- A folder with Team notes updated on one computer while the other has `AGENTS.md` open.
- The 2.12.0 computer opening the folder after the update and pressing Update, then the 2.12.1 computer opening it again, seeing the old copy named, with its path, as safe to delete by hand.

## What covers it instead

Automated tests in `./test/run.sh`:

- **The text:** `test/assistant-start.test.js` checks `AGENTS.md` is at most 28 KiB, that its safety rules come first, that every sentence of 2.12.0's text is still in `AGENTS.md` or the file formats, and that no rule moved out of `AGENTS.md`.
- **Upgrading:** a folder installed by 2.12.0's own command, with Team notes, upgrades with `flightdeck install` and with Settings to the same files and the same record; a team's own change to Flightdeck's part waits to merge; something in the way of the new file stops both before anything is written.
- **Older copies:** 2.11.1's and 2.12.0's apps, from the release tags, on a folder this version installed. The real path runs 2.12.0's page from the tag: Update on a folder 2.12.1 installed, then this version's Settings, Folder health, `install --check` and `install`, which name the old copy and never offer it for merging.
- **A newer record:** a well-formed record whose version is newer than this copy is left alone by the command, Settings and Folder health, through one function (`PF.contract.recordNewer`, which the command runs from its own app file, with the app's own record parser), in the same words. A malformed record, a version with a leading zero or an absurd one is ignored, never newer, and Folder health says it can't be read.
- **Old copies:** which waiting copies count as old (`PF.contract.classifyCopies`, the one function the app's scan, Settings, Folder health and the command all use), case by case; a copy with a Team note or merge note, Windows line endings or a byte-order mark stays a merge in the app and the command alike (the test folder's `File.text()` drops a byte-order mark as a browser's does, so a test can't miss one); a customized skill whose default didn't change keeps its pending merge through Update; an old copy is decided again on every read (once the file is a customized older version, it's a merge again); and with every AI assistant files button pressed, an old copy is still where it was, byte for byte, with nothing filed away.
- **Everything else on saving and reads:** `test/assistant-files.test.js`, `test/sync.test.js`, `test/folder.test.js`, `test/app.test.js`, and the compat tests from older releases' shipped code.

## What isn't proven on real OneDrive

- The new `AGENTS.md` and the file formats arriving on a second computer, and what OneDrive does if that computer changed `AGENTS.md` at the same moment.
- A real AI assistant on the second computer reading the new `AGENTS.md` before the file formats have arrived.

## Limits that are known and kept

- **2.12.0's app on a folder 2.12.1 installed:** 2.12.0 has shipped and can't change. It reads a record from a newer version as its own, so its Folder health asks for `AGENTS.md` to be merged, and its Update writes its older default to `.flightdeck/updates/2.12.0/` and the record back to 2.12.0. `AGENTS.md` and the file formats are left as they are. 2.12.1 then names that copy as an old copy left by an older app: `install --check` and Folder health don't count it, nothing asks for it to be merged, Settings and Folder health name it with its path as safe to delete by hand. Nothing removes it. 2.12.0's command refuses the folder as newer. From 2.12.1 on, a copy reading a folder a newer version set up leaves it alone.
- **No Put away:** an old copy stays in `.flightdeck/updates/` until someone deletes it by hand. A button to file it away was cut from this release (docs/design.md, section 42) and comes back with its own reviewed design.
