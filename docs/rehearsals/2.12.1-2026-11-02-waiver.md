# Two-computer rehearsal waived (not rehearsed): Flightdeck 2.12.1

- Version: 2.12.1
- Date: 2026-11-02
- Decision: the project owner waived the two-computer rehearsal (docs/rehearsals/README.md, *The release gate*) for this release.

## Why it was asked for

2.12.1 is a patch, so the gate doesn't require a rehearsal. `src/storage/` and the run and notes formats aren't touched, and `mutateRun`, `canReplace`, `recover`, `applyRunRead`, `useFs`, `acceptProposal` and `queued` are byte for byte as in 2.12.0. It does ship a new `AGENTS.md` and a new file in the team folder, `.flightdeck/skills/_flightdeck/file-formats.md`, written by the existing writers, `flightdeck install` and Settings > AI assistant files, with the same rules and record. Copy instructions and Download skills ZIP write nothing to any folder. It also changes how a record from a newer version and an old copy left by an older app are read (below), and adds Put away, which files an old copy away through the same `repo.archiveStaged` that I merged it uses.

## What the rehearsal would have covered

On a test folder, with one computer on 2.12.0 and the other on 2.12.1:

- Update on one computer, then the other computer seeing the new `AGENTS.md`, the file formats, the record and Folder health's result.
- A folder with Team notes updated on one computer while the other has `AGENTS.md` open.
- The 2.12.0 computer opening the folder after the update and pressing Update, then the 2.12.1 computer opening it again, seeing the old copy named and putting it away.

## What covers it instead

Automated tests in `./test/run.sh`:

- **The text:** `test/assistant-start.test.js` checks `AGENTS.md` is at most 28 KiB, that its safety rules come first, that every sentence of 2.12.0's text is still in `AGENTS.md` or the file formats, and that no rule moved out of `AGENTS.md`.
- **Upgrading:** a folder installed by 2.12.0's own command, with Team notes, upgrades with `flightdeck install` and with Settings to the same files and the same record; a team's own change to Flightdeck's part waits to merge; something in the way of the new file stops both before anything is written.
- **Older copies:** 2.11.1's and 2.12.0's apps, from the release tags, on a folder this version installed. The real path runs 2.12.0's page from the tag: Update on a folder 2.12.1 installed, then this version's Settings, Folder health, `install --check` and `install`, which name the old copy and never offer it for merging.
- **A newer record:** a record whose version is newer than this copy is left alone by the command, Settings and Folder health, through one function (`PF.contract.recordNewer`, which the command runs from its own app file), in the same words.
- **Old copies:** which waiting copies count as old (`PF.contract.oldCopy`), case by case; a copy changed by one character stays a merge; Put away reads the copy again and leaves one that changed.
- **Everything else on saving and reads:** `test/assistant-files.test.js`, `test/sync.test.js`, `test/folder.test.js`, `test/app.test.js`, and the compat tests from older releases' shipped code.

## What isn't proven on real OneDrive

- The new `AGENTS.md` and the file formats arriving on a second computer, and what OneDrive does if that computer changed `AGENTS.md` at the same moment.
- A real AI assistant on the second computer reading the new `AGENTS.md` before the file formats have arrived.

## Limits that are known and kept

- **2.12.0's app on a folder 2.12.1 installed:** 2.12.0 has shipped and can't change. It reads a record from a newer version as its own, so its Folder health asks for `AGENTS.md` to be merged, and its Update writes its older default to `.flightdeck/updates/2.12.0/` and the record back to 2.12.0. `AGENTS.md` and the file formats are left as they are. 2.12.1 then names that copy as an old copy left by an older app: `install --check` and Folder health don't count it, nothing asks for it to be merged, and Put away files it with the replaced files. Nothing removes it on its own. 2.12.0's command refuses the folder as newer. From 2.12.1 on, a copy reading a folder a newer version set up leaves it alone.
- **Put away:** like I merged it, a change that lands between the last read of the copy and its removal is lost with that generated copy.
