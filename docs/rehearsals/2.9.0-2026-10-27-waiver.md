# Two-computer rehearsal waived (not rehearsed): Flightdeck 2.9.0

- Version: 2.9.0
- Date: 2026-10-27
- Decision: the project owner waived the two-computer rehearsal (docs/rehearsals/README.md, *The release gate*) for this release.

## Why it was required

2.9.0 adds a new file to the team folder (`team-values.json`, family `flightdeck-team-values`) and a new required feature to existing formats: `team-values` on a version (preflight-publication/2) and its runs (preflight-run/3), from a `pass:` entry with a `team:` source. It also changes `src/storage/` (`readTeamValues`, `saveTeamValues`, `saveChecked`'s bounded reads, and `saveRun`'s awaited `prewrite`) and the saving code in `src/ui/app.js` (a child's start reads team values again right before it writes). By the rule in docs/rehearsals/README.md, it needs the rehearsal.

## What the rehearsal would have covered

The script's steps and the accounting tally, run once with both computers on 2.9.0 and once with one on 2.8.0, on a test folder holding:

- team values edited in Settings on both computers while one is offline (the second save is refused and asks for the change again; OneDrive's conflict copy is listed in Folder health);
- a child started on computer A while computer B changes the team value it passes (nothing starts on A once the change arrives, and the form opens again with the new value);
- a checklist that passes a team value (2.8.0 names it "needs Flightdeck 2.9" and starts nothing).

## What covers it instead

Automated tests in `./test/run.sh`, all green on the release commit:

- **Older copies, from their own shipped code**: `test/compat-teamvalues.test.js` (every recorded copy from 1.11.1 to 2.8.0 refuses a version that passes a team value, and its run, by name, writes nothing and leaves `team-values.json` alone), plus `test/compat.test.js` (the reader inventory) and `test/compat-bridge.test.js` (a newer `team-values.json` refused and named).
- **The file**: `test/teamvalues.test.js` (reading, limits, bounded reads and saves, publish and stage checks, Folder health, `prewrite`, the parent's record) and `test/checker.test.js` (the Python checker agrees).
- **The app**: `test/app-teamvalues.test.js` (Settings with a conflict, the start with a set, missing, damaged or non-converting value, a change while the form is open or while the child saves, an older refresh landing late, the retry rules, Link it's confirm) and `test/guide-editor.test.js` (the builder).
- **Two computers, simulated**: `test/sync.test.js` and the app tests' paused races.

Code review passed in 9 rounds; every problem found has a test that fails without its fix.

## What isn't proven on real OneDrive

- A team value changed on one computer while a child starts on the other, over real sync delays: the check right before the write sees only what has arrived.
- Two owners saving team values at once across computers: the read-back catches a write that lands between Flightdeck's write and its read-back, not one that lands later (OneDrive keeps both copies; Folder health lists the copy).
- A mixed team (2.8.0 and 2.9.0) over real sync delays.

## What still runs by hand

The one-computer browser check in Edge and Chrome from a real `file://` path: add a team value in Settings, pass it from a linked step, publish, start a run and start the child from the step.
