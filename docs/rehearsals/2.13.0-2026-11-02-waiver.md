# Two-computer rehearsal waived (not rehearsed): Flightdeck 2.13.0

- Version: 2.13.0
- Date: 2026-11-02
- Decision: the project owner waived the two-computer rehearsal (docs/rehearsals/README.md, *The release gate*) for this release.

## Why it was asked for

2.13.0 is a minor release. The plan for it expected to move publishing's checks into `src/storage/`, which the gate covers. It didn't. In `src/storage/`, only `src/storage/repo.js` changed: `loadStepTypes` and `loadWorkflows` also return `over`, the step types past the first 100 and the Jira issue types past the first 50 they already leave out, so `flightdeck draft check` can name them. The app ignores the new field, and what the loaders read, keep and return otherwise is as in 2.12.2. The rest of `src/storage/`, the run and notes formats, the connection check and `mutateRun`, `canReplace`, `recover`, `applyRunRead`, `useFs`, `acceptProposal` and `queued` are byte for byte as in 2.12.2. What changed is in `src/core/publish.js` and the screens: `PF.publish.checkOptions` now builds the inputs the editor's Checks, Review & publish and a proposal's checks pass to the checker, and `publish.build` finds `version:` pins through a helper `flightdeck draft check` shares. The new command, `flightdeck draft check`, only reads. `flightdeck draft read`, `save` and `propose` return the same complete checks. It ships a new `AGENTS.md` and new review, new-checklist and edit-checklist skills, written by the existing writers, `flightdeck install` and Settings > AI assistant files, with the same rules and record as 2.12.2.

## What the rehearsal would have covered

On a test folder, with one computer on 2.12.2 and the other on 2.13.0:

- Publishing a draft that uses a team step type, a Jira transition and linked checklists on 2.13.0, and the other computer seeing the version and starting a run from it.
- Update on one computer, then the other computer seeing the new `AGENTS.md`, the skills, the record and Folder health's result.

## What covers it instead

Automated tests in `./test/run.sh`:

- **The same verdict as the app:** `test/cli-parity.test.js` runs `flightdeck draft check` and this build's app (the process page's checks, then Publish through `repo.publish`) on the same folders, and requires the same blockers, tips and publish verdict, word for word and in order: team step types, unknown types, reserved names, every Jira case, people, linked children published and not, `version:` pins, published parents, team values, screenshots, and `constructor`, `__proto__` and `toString` as process, type and person IDs.
- **What couldn't be read:** the same file makes `people.json`, a step type, `step-types/`, `jira/workflows.json`, `publications/`, a child's or a parent's versions, and a screenshot unreadable or newer, or past the step-type and Jira limits, and requires a partial answer that names it and gives no blocker or tip the readable folder doesn't.
- **Publishing unchanged:** the app, staging, pins and publish tests of 2.12.2 run unchanged; the roles comparison runs against 2.12.2's shipped page.
- **The text:** `test/assistant-start.test.js` checks `AGENTS.md` is at most 28 KiB and that every sentence of 2.12.0's text is still there or listed with its new words; `test/docs.test.js` checks `AGENTS.md` and `docs/apps.md` name every command in the help.
- **Upgrading and older copies:** the install, Settings and upgrade tests run against the new defaults, recorded in `src/baselines.json` for 2.13.0, and the cross-version tests run every recorded release, now with 2.12.2.

## What isn't proven on real OneDrive

- A version published on 2.13.0 arriving on a computer on 2.12.2, and the new `AGENTS.md` and skills arriving while that computer has one open.

## Limits that are known and kept

- **What only the app's window knows:** an editor's unsaved text and a screenshot still being added hold Publish in the app; `draft check` checks what's in the folder.
- **A minute behind:** `draft check` reads this computer's copy of the folder, which another computer may be ahead of.
