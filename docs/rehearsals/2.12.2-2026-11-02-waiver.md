# Two-computer rehearsal waived (not rehearsed): Flightdeck 2.12.2

- Version: 2.12.2
- Date: 2026-11-02
- Decision: the project owner waived the two-computer rehearsal (docs/rehearsals/README.md, *The release gate*) for this release.

## Why it was asked for

2.12.2 is a patch, so the gate doesn't require a rehearsal. It changes no code in `src/` or `bin/`: `src/storage/`, the run and notes formats, the connection check and `mutateRun`, `canReplace`, `recover`, `applyRunRead`, `useFs`, `acceptProposal` and `queued` are byte for byte as in 2.12.1. It does ship a new `AGENTS.md` and a new `flightdeck-review-checklist` skill, written by the existing writers, `flightdeck install` and Settings > AI assistant files, with the same rules and record as 2.12.1. Both now say what the checks `flightdeck draft` returns really load (the processes linked steps start and the team values they name, since 2.8 and 2.9) and what they don't (people, step types, Jira workflows and which processes are published), and `AGENTS.md`'s table of what an assistant may do lists `flightdeck export`. `docs/apps.md` lists `flightdeck skill register` and `flightdeck export`.

## What the rehearsal would have covered

On a test folder, with one computer on 2.12.1 and the other on 2.12.2:

- Update on one computer, then the other computer seeing the new `AGENTS.md`, the review skill, the record and Folder health's result.
- A folder with Team notes updated on one computer while the other has `AGENTS.md` open.

## What covers it instead

Automated tests in `./test/run.sh`:

- **The text:** `test/assistant-start.test.js` checks `AGENTS.md` is at most 28 KiB, that its safety rules come first, and that every sentence of 2.12.0's text is still in `AGENTS.md` or the file formats. The two sentences on what draft checks load are reworded, each listed with its new words, and no rule moved out of `AGENTS.md`.
- **The commands:** `test/docs.test.js` checks that `AGENTS.md` and `docs/apps.md` name every command in the command's help (those a person runs to set up or look after the folder are left to the README, which must name them), and that the check sees one left out.
- **Upgrading and older copies:** the install, Settings and upgrade tests of 2.12.1 run unchanged against the new defaults, recorded in `src/baselines.json` for 2.12.2; 2.12.1's shipped page, from the release tag, is now one of the old copies the cross-version tests run, and the roles comparison runs against it.
- **Everything else on saving and reads:** `test/assistant-files.test.js`, `test/sync.test.js`, `test/folder.test.js`, `test/app.test.js`, and the compat tests from older releases' shipped code.

## What isn't proven on real OneDrive

- The new `AGENTS.md` and review skill arriving on a second computer, and what OneDrive does if that computer changed `AGENTS.md` at the same moment.

## Limits that are known and kept

- **The checks are still incomplete.** Only the words change: a team step type still shows as an unknown type, Jira transitions still aren't checked against `jira/workflows.json` and can get a false suggestion, and every linked process and owner is still suggested as missing. A later release loads them.
- **2.12.1's app on a folder 2.12.2 installed** reads a record from a newer version and leaves the folder alone, as 2.12.1 does for any newer version.
