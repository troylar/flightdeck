# Two-computer rehearsal waived (not rehearsed): Flightdeck 2.15.0

- Version: 2.15.0
- Date: 2026-11-03
- Decision: the project owner waived the two-computer rehearsal (docs/rehearsals/README.md, *The release gate*) for this release.

## Why it was asked for

2.15.0 is a minor release that changes what the AI assistant files say and when an update writes `AGENTS.md`. The release gate isn't required: nothing changed in `src/storage/`, the run or notes formats, the connection check, or the gated functions (`queued`, `canReplace`, `applyRunRead`, `useFs`, `acceptProposal`, `mutateRun`, `recover`), each byte for byte as in 2.14.0. `AGENTS.md` keeps its rules and points to two new files, `.flightdeck/skills/_flightdeck/command-guide.md` and `checklist-essentials.md`, which say how. An update now holds `AGENTS.md` back (staged with the file it points to) while a file it would point to is waiting to be merged and lacks a section it names. The waiver is recorded anyway, because that hold spans two files that sync separately.

## What the rehearsal would have covered

On a test folder, with one computer on 2.14.0 and the other on 2.15.0:

- Update on 2.15.0, then the other computer receiving the new `AGENTS.md` and the two new files, in whatever order OneDrive delivers them.
- A held merge: a team-changed command guide and `AGENTS.md` staged together on one computer, merged and finished on the other.
- Folder health and Settings > AI assistant files on both computers while the files arrive.

## What covers it instead

Automated tests in `./test/run.sh`:

- **The rule inventory:** `test/agents-inventory.test.js` proves every unit of 2.14.0's `AGENTS.md` (`test/fixtures/agents-2.14.0.md`) is in the new `AGENTS.md` or moved word for word to a section of a new file, that the rules stay where they were, that nothing added grants what `AGENTS.md` forbids, and that every pointer names a real section; each of its 67 breaks fails exactly the rules it should.
- **The content rule:** `test/assistant-start.test.js` runs each hold case through the command, Settings and Folder health, requires the three to agree, and requires that no file `AGENTS.md` points to lacks a section its own default has after any install.
- **The words:** the README in the updates folder, the line `flightdeck install` prints and Folder health say which file and which sections, in each case.
- **The routed commands:** `test/docs.test.js` requires every command in the help to have one row in the Commands table, routed to a place that names it in full.
- **Older copies and upgrades:** the install, Settings and upgrade tests run against the new defaults, recorded in `src/baselines.json` for 2.15.0, and the cross-version tests run every recorded release, now with 2.14.0.

## What isn't proven on real OneDrive

- A second computer receiving `AGENTS.md` before `_flightdeck/`.
- A held merge staged on one computer and finished on another.

## Limits that are known and kept

- **A minute behind:** an update reads this computer's copy of the folder, which another computer may be ahead of.
- **A heading the reader doesn't see** (a setext heading, one in a block quote or an HTML comment, another letter case): the file counts as lacking that section, so it is staged again and Folder health names the section.
