# Two-computer rehearsal waived (not rehearsed): Flightdeck 4.0.0

- Version: 4.0.0
- Date: 2026-11-10
- Decision: the project owner waived the two-computer rehearsal (docs/rehearsals/README.md, *The release gate*) for this release, under the owner's standing rule that a waiver is recorded, not asked for. No rehearsal is planned.

## Why it was asked for

4.0.0 adds living runs: to-dos a run takes on while it runs, kept as to-do records in `proposals/` (`flightdeck-plan/4`, `flightdeck-plan-status/4`) and landed by the recorder's window into `run.json` (`preflight-run/3` naming `living-runs`), with spreads, facts, keeps, checklist-linked to-dos, plan versus now and the receipt a living run ends with. Several windows on several computers write those records at once, and the recorder's window lands them through the checked save chain, so how they meet on a real synced folder is what a rehearsal would show. A run without to-dos reads and saves as in 3.0.

## What the rehearsal would have covered

On a test folder, with two computers on 4.0.0 and a third on 3.0.0: to-dos asked, decided and delegated on one computer while the recorder's window on the other lands them; a spread added and synced to a loop's stories; facts filed by a tool; a living run ended with its receipt while a request arrives on the other computer; an evidence pack made of that run; and the 3.0.0 computer opening the same folder.

## What covers it instead

Automated tests in `./test/run.sh`, all passing on the release commit: the to-do, spread, fact, keep, checklist-linked and receipt rules (`test/todos*.test.js`, `test/spreads*.test.js`, `test/facts.test.js`, `test/learn.test.js`, `test/detours.test.js`, `test/receipts.test.js`), the app suites (`test/app-todos*.test.js`, `test/app-spreads.test.js`, `test/app-facts.test.js`, `test/app-learn.test.js`, `test/app-detours.test.js`, `test/app-receipts.test.js`: interrupted writes, a person switched mid-write, a request landing between the receipt and the run's save), the command and checker parity rules (`test/checker-todos.test.js`, `test/*-cli.test.js`), the evidence rules (`test/evidence-living.test.js`, with Python's independent replay of the chain), and the cross-version tests against the exact shipped 3.0.0 (`test/compat-todos.test.js`, `test/compat-receipts.test.js`).

## What isn't proven on real OneDrive

How to-do records, applications and receipts written on one computer arrive on another while OneDrive is still syncing (late, out of order, or as conflict copies), and how the recorder's window behaves on a folder that is a minute behind. The tests stand in for OneDrive with in-memory and on-disk folders; real-OneDrive behavior is unproven.
