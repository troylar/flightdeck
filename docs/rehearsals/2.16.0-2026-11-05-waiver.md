# Two-computer rehearsal waived (not rehearsed): Flightdeck 2.16.0

- Version: 2.16.0
- Date: 2026-11-05
- Decision: the project owner waived the two-computer rehearsal (docs/rehearsals/README.md, *The release gate*) for this release, under the owner's standing rule that a waiver is recorded, not asked for.

## Why it was required

2.16.0 changes the run file format. A run of a checklist with a `{jira.search}` step gains `searchSites` (the Jira address copied when it started), `searchGen` (a generation for each run detail) and `searchRec` (a recovery generation for each search step), and a blocked search may keep its results (Block with these). When a run is read, a checked search whose record no longer stands is reopened in that copy, and a completed run's damaged generations are rebuilt. `src/storage/repo.js` gains one read-only value, `childMarks`, beside the runs it loads. The gated functions (`queued`, `canReplace`, `applyRunRead`, `useFs`, `acceptProposal`, `mutateRun`, `recover`) are byte for byte as before.

The release also carries the AI assistant files change (`AGENTS.md` keeps its rules and points to two new files, `.flightdeck/skills/_flightdeck/command-guide.md` and `checklist-essentials.md`; an update holds `AGENTS.md` back while a file it points to is waiting to be merged and lacks a section it names), which spans two files that sync separately, and new screens (one workspace per checklist, one header, Back), which change nothing in the team folder.

## What the rehearsal would have covered

On a test folder with a checklist that has Jira search steps, both computers on 2.16.0:

- Two computers reading one run with `searchSites` and `searchGen`.
- A detail changed on one computer while the other records a search's results.
- The detail changed back to its old value: the results recorded for the earlier generation stay refused.
- A conflict copy adopted, and an older browser copy restored: every search gets fresh generations and its results go to history.
- Adoption back and forth between the two computers.

And with one computer on 2.14.0 and the other on 2.16.0, for the AI assistant files:

- Update on 2.16.0, then the other computer receiving the new `AGENTS.md` and the two new files, in whatever order OneDrive delivers them.
- A held merge: a team-changed command guide and `AGENTS.md` staged together on one computer, merged and finished on the other.
- Folder health and Settings > AI assistant files on both computers while the files arrive.

## What covers it instead

Automated tests in `./test/run.sh`:

- `test/search-runs.test.js`: generations at start, the record-time check, Block with these, corrections, a detail changing A to B to A, Refresh search, recovery, and the reader's reopen, each refusal leaving the run as it was.
- `test/search-linked.test.js`: a linked child whose search was reopened, the folder mark, and the link-time height and budget walk.
- `test/search-reports.test.js`: report acceptance against the run at that moment, and the `search` object in the commands.
- `test/search-screen.test.js`: the run screen.
- The compatibility, recovery and save round-trip suites (`compat-*.test.js`, `save.test.js`, `failed-reads.test.js`, `sync.test.js`) on the new format.
- **The rule inventory:** `test/agents-inventory.test.js` proves every unit of 2.14.0's `AGENTS.md` (`test/fixtures/agents-2.14.0.md`) is in the new `AGENTS.md` or moved word for word to a section of a new file, that the rules stay where they were, that nothing added grants what `AGENTS.md` forbids, and that every pointer names a real section; each of its 67 breaks fails exactly the rules it should.
- **The content rule:** `test/assistant-start.test.js` runs each hold case through the command, Settings and Folder health, requires the three to agree, and requires that no file `AGENTS.md` points to lacks a section its own default has after any install.
- **The words:** the README in the updates folder, the line `flightdeck install` prints and Folder health say which file and which sections, in each case.
- **The routed commands:** `test/docs.test.js` requires every command in the help to have one row in the Commands table, routed to a place that names it in full.
- **Older copies and upgrades:** the install, Settings and upgrade tests run against the new defaults, recorded in `src/baselines.json` for 2.16.0, and the cross-version tests run every recorded release, now with 2.14.0.

## What isn't proven on real OneDrive

- A detail change and a recorded result arriving on another computer in either order.
- A conflict copy of a run with search generations, adopted on the other computer.
- A second computer receiving `AGENTS.md` before `_flightdeck/`.
- A held merge staged on one computer and finished on another.

## Limits that are known and kept

- **Reads don't write.** A reopened search is reopened in each copy as it's read; the file keeps the done answer until someone answers the step again.
- **A copy made by a newer Flightdeck** (fields this copy doesn't know) is shown read-only and isn't reopened.
- **A minute behind:** an update reads this computer's copy of the folder, which another computer may be ahead of.
- **A heading the reader doesn't see** (a setext heading, one in a block quote, another letter case): the file counts as lacking that section, so it is staged again and Folder health names the section.
- **A heading inside an HTML comment counts:** the reader doesn't look for `<!-- ... -->`, so a section commented out still counts as there, and AGENTS.md isn't held for it.
