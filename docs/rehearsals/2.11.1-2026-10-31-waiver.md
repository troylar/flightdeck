# Two-computer rehearsal waived (not rehearsed): Flightdeck 2.11.1

- Version: 2.11.1
- Date: 2026-10-31
- Decision: the project owner waived the two-computer rehearsal (docs/rehearsals/README.md, *The release gate*) for this release.

## Why it was asked for

2.11.1 is a patch, so the gate doesn't require a rehearsal, but it changes what the saving code in `src/ui/app.js` looks up. `state.unsaved`, `state.saveErr`, `state.saveOpts`, `state.pendingSaves`, each run's edit count and its baseline for Discard are now made without a prototype, so a run with an id like `constructor` reads nothing inherited. `mutateRun`, `canReplace`, `recover`, `applyRunRead`, `useFs`, `acceptProposal` and `queued` are byte for byte as in 2.11.0; `save` only stopped creating `state.pendingSaves` and `state.saveOpts`, which now always exist. `src/storage/`, the connection check and the run and notes formats aren't touched, and receipts and Copy for Jira are as they were. A run file's step or gate keyed `__proto__` is dropped as it is read rather than setting what the run's answers inherit; saving already dropped it. A run whose own checklist names a step, phase, gate, role or detail like `constructor` (only a hand edit gets one) is read-only.

## What the rehearsal would have covered

The script's steps 4 to 13 and the bad night's steps 14 to 20, on a test folder with a running run whose id is `constructor`, once with both computers on 2.11.1. On 2.11.0 a folder with such a run doesn't open, so a mixed team can't reach this. Also step 7 with two notes sharing an id, each with a screenshot.
