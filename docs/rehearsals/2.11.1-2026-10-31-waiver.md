# Two-computer rehearsal waived (not rehearsed): Flightdeck 2.11.1

- Version: 2.11.1
- Date: 2026-10-31
- Decision: the project owner waived the two-computer rehearsal (docs/rehearsals/README.md, *The release gate*) for this release.

## Why it was asked for

2.11.1 is a patch, so the gate doesn't require a rehearsal, but it changes what the saving code in `src/ui/app.js` looks up. The protections differ by dictionary:

- `state.unsaved`, `state.saveErr`, `state.saveOpts` and `state.pendingSaves` lose their prototype when assigned, through a setter on `state`, so the `{}` that `useFs` assigns to them on a folder switch has none either.
- `editCount` stays a plain `{}`. `edits(id)` reads it with an own-property check.
- `baselines` starts without a prototype, but `useFs` resets it to a plain `{}`. Discard reads it with an own-property check. `applyRunRead` installs a baseline for each run it reads, unconditionally, so a run named `constructor` has its own baseline before it is picked up or edited, and Discard puts that back, even after a folder switch.

`mutateRun`, `canReplace`, `recover`, `applyRunRead`, `useFs`, `acceptProposal` and `queued` are byte for byte as in 2.11.0; `save` only stopped creating `state.pendingSaves` and `state.saveOpts`, which now always exist. `src/storage/`, the connection check and the run and notes formats aren't touched, and receipts and Copy for Jira are as they were. A run file's step or gate keyed `__proto__` is dropped as it is read rather than setting what the run's answers inherit; saving already dropped it. A run whose own checklist names a step, phase, gate, role or detail like `constructor` (only a hand edit gets one) is read-only.

## What the rehearsal would have covered

The script's steps 4 to 13 and the bad night's steps 14 to 20, on a test folder with a running run whose id is `constructor`, once with both computers on 2.11.1. On 2.11.0 a folder with such a run doesn't open, so a mixed team can't reach this. Also step 7 with two notes sharing an id, each with a screenshot.

## What covers it instead

Automated tests in `./test/run.sh`:

- **Names**: `test/patch-2111.test.js`. A running run named `constructor`, `toString`, `hasOwnProperty` or `valueOf` is read twice with the rest of the folder. `__proto__` isn't a valid run ID, so a run file with it is left out, and its test checks that it is left out and the rest of the folder still reads. Only `constructor` goes through the whole sequence: recorded in, saved, a failed save said, that save discarded, the run in memory back as it was saved, and the next save without the discarded answer. People, a checklist named `constructor`, a Jira workflow named `__proto__` (its required field is refused when missing and recorded when given, before and after the run is written and read), rotation and solo have their own tests. A frozen step type naming evidence, a field or a condition like `constructor` or `__proto__` isn't run, by the app and by the assistants' checker alike, read from the folder's files.
- **Twins**: `test/patch-2111.test.js`. Each attachment button opens the image or file of the note it carries, in a step's notes and corrections, on Finish, on the receipt and on a checklist's page, checked by the file it reads; a stale button when a third copy has arrived opens nothing; closing an image returns focus to the note's own button after the notes reorder or page, or to the list's heading when the note is gone; Save a copy is pressed and its name and bytes checked; each correction row's status is checked on the run and on Finish; Withdraw is pressed and the decision's group checked. Each of these tests was shown to fail with the behavior broken in a scratch copy.
- **Saving and reads**: `test/sync.test.js`, `test/app.test.js`, `test/find-twins.test.js`, `test/find-r21.test.js` and `test/find-r22.test.js`.
- **Older copies, from their own shipped code**: `test/compat.test.js`, `test/compat-bridge.test.js` and `test/old-bundles.test.js`, with 2.11.0 now recorded as an older release.
- **A headless Chromium check on the big folder**, handed over as a picked folder, with a check for each bug, including where focus lands after closing a zoomed image.

## What isn't proven on real OneDrive

- A run with an id like `constructor` saved and read back over real sync delays, including a conflict copy of it.
- A Jira workflow named `__proto__` on a mixed team. An older copy opens such a run as it always did, without that workflow, so it doesn't ask for that workflow's fields, and its save writes the run without it.
- Two runs in two processes sharing a run id, which still lose an unsaved edit in both 2.11.0 and 2.11.1; the protected saving code keys by id alone.
