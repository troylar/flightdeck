# Two-computer rehearsal waived (not rehearsed): Flightdeck 2.0.0

- Version: 2.0.0
- Date: 2026-10-21
- Decision: the project owner waived the two-computer rehearsal (docs/onedrive.md, *Release gate*) for this release.

## Why it was required

2.0.0 is a major release. It writes new file formats (`preflight-publication/2`, `preflight-run/3`, `flightdeck-plan/2`, `flightdeck-plan-status/2`, `flightdeck-skill/2`, `flightdeck-step-type/2`), new folders (`skill-registrations/`, `reports/`, `report-decisions/`), and corrections on a phase's or a gate's note (`cv: 2`). It changes `src/storage/` and the saving code in `src/ui/app.js` (accepting a report saves the run's answer before its decision is written). By the rule in docs/onedrive.md, it needs the rehearsal.

## What the rehearsal would have covered

The script's steps 0 to 23, P and R, and the accounting tally, run once with both computers on 2.0.0 and once with one computer on 1.21 and one on 2.0 (docs/onedrive.md, *Older copies*), on a test folder holding:

- a checklist that uses nothing new (it must publish as `/1`, and both computers record on it as before);
- a checklist with a phase note and phase and gate screenshots, a pinned linked run (`version: N`), a typed run detail and typed evidence (it must publish as `/2`; the 1.21 computer names it "Needs Flightdeck 2.0" and starts nothing);
- a run started on 1.21 that reaches a step whose linked checklist needs 2.0 (Start it as a Flightdeck 2.0 run on the 2.0 computer; the 1.21 computer reads the step as Continued);
- a report written by `flightdeck report write` on one computer and accepted, then another declined, by the recorder on the other;
- a correction on a phase's note made on 2.0 and read on 1.21 as a described problem;
- `flightdeck skill register` on one computer and the skill step checked on the other.

## What covers it instead

Automated tests in `./test/run.sh`, all green on the release commit:

- **Older copies, from their own shipped code** (`test/compat-harness.js`, every tag recorded from 1.10.0 to 1.22.0, with the floor at 1.11.1): `test/compat.test.js` (what each release does with a team folder, saving and recovery in the app harness), `test/compat-bridge.test.js` (every 2.0 family refused by name, saves refused with zero writes), `test/compat-formats.test.js` (this version's `/1` version and run/2 read and recorded by 1.11.1 to 1.22.0; the `/2` version and run/3 refused, nothing started or written), `test/compat-pins.test.js` (pinned versions, plan/2, skill registrations and the run/3 continuation of an old run, with a run/2 parent handed between versions), `test/compat-typed.test.js` (typed publications, runs and step types refused by name), and `test/old-bundles.test.js` (the shipped pages of older releases on files this version writes).
- **File formats**: `test/envelope.test.js` (every family, its legacy spellings, the lowest sufficient format, and the frozen 2.0 samples byte for byte; staging, test runs and extensions stay refused).
- **Pins**: `test/pins.test.js` (nothing falls back to the latest; a run/3 field this copy can't keep makes the run read-only).
- **Reports**: `test/reports.test.js` and `test/app-reports.test.js` (written once, read back byte for byte; a decision is written only after the run's save holds the accepted answer; a decision that can't be read holds every acceptance).
- **Typed values**: `test/typed.test.js` (conversions only when certain; a stored value that isn't valid is shown as written, never rewritten; over-long run/3 text makes the run read-only).
- **The lightness pass**: `test/light.test.js` and `test/light-views.test.js` (folded panels stay reachable; Publish waits for unsaved edits; stored values are unchanged by the plain words on screen).
- **Two computers, simulated**: `test/sync.test.js` (delayed sync, hand-off, take over, conflict copies) and `test/app.test.js` (the built app with races paused at exact points).

## What isn't proven on real OneDrive

- How long a `/2` version's files (its screenshots and payload) take to arrive, and that the other computer shows it as still syncing until they all match.
- A report and its decision arriving at different times on the recorder's computer and on another.
- A mixed team (1.21 and 2.0) over real sync delays, including Folder health naming the older copy from its connection checks.

## What still runs by hand

The one-computer browser check in Edge and Chrome from a real `file://` path (Windows `file:///C:/…` and a OneDrive path): publish a checklist with phase notes and screenshots and run it; a typed start form; accept and decline a report; the four top-bar sections, the folded process page and Home as an owner and as someone else; New process by title; screen reader on the folds.
