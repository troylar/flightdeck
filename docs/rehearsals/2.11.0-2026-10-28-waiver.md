# Two-computer rehearsal waived (not rehearsed): Flightdeck 2.11.0

- Version: 2.11.0
- Date: 2026-10-28
- Decision: the project owner waived the two-computer rehearsal (docs/rehearsals/README.md, *The release gate*) for this release.

## Why it was required

2.11.0 changes no file format and writes nothing new to the team folder. It doesn't touch `src/storage/` or the connection check, and none of `mutateRun`, `canReplace`, `recover`, `applyRunRead`, `useFs`, `acceptProposal` or `queued` in `src/ui/app.js` changed. Two changes sit close to the saving and sync code, though: adding a note now creates the note's id before the write, so the note just saved can be drawn and brought into view after the refresh; and `renderNow` keeps focus and scroll across redraws for rows that are paged, kept or just shown, including rows whose id holds a `#` or `/`. Neither changes what is written or how a read of the folder is applied, but under "When in doubt, rehearse" in docs/rehearsals/README.md the release is recorded as needing the rehearsal.

## What the rehearsal would have covered

The script's steps and the accounting tally, run once with both computers on 2.11.0 and once with one on 2.10.0, on a test folder holding:

- a note added on computer A while computer B adds notes on the same step (both arrive, in time order, and A's new note is drawn even when it sorts outside the newest 20);
- a follow-up's Won't do or Moved to form open on A while B decides or removes that follow-up (A keeps what it typed, marked "No longer open" or "Removed elsewhere");
- a note, correction or report opened from search on A while B's newer copy of the run arrives (the same note stays shown, found by its content, or the slot says it's gone);
- notes added on 2.11.0 and read on 2.10.0, and the reverse (they read the same).

## What covers it instead

Automated tests in `./test/run.sh`, all green on the release commit:

- **Every long list bounded, on one big folder**: `test/bounds-app.test.js` (1,000 checklists, 500 people, 5,000 follow-ups, 10,000 running runs, a step with 300 notes and the rest of the plan's sizes; every screen, fold, dialog and form, with a registry of bounded lists, a catch-all for any list it doesn't know, and `PF.vk.PAGE_OFF` proving the check notices) and `test/scale-app.test.js` (rows built only for the page, and typing surviving a batch draw: a step note, a Fill in value and a follow-up reason keep their text, focus and caret).
- **The list helper, focus and sort**: `test/find.test.js` (`K.list`'s page, kept and just-shown rows, tail and dialog; `K.byId` for any id a file can hold; Show more focusing the first row it adds; Find on Checklists and Skills, its reset on a folder switch without a change to `useFs`; natural sort and people by name, with `people.json`, the CLI and the outside-app JSON keeping file order).
- **Rows being edited kept through newer reads**: `test/find-runs.test.js` (an open Won't do or Moved to form kept through Show more, Find, Open/Yours/All and a newer read that decides or removes the follow-up; Moved to's choice kept when its run ends or is removed or its plan starts, with Save writing exactly the reference 2.10 writes; bounded dropdowns; Just planned) and `test/find-process.test.js` (a correction being declined and a report's decline reason kept through a newer read; search, View correction and panel links opening rows past the page; a correction just saved drawn and focused).
- **The add-note path and notes sharing an id**: `test/find-notes.test.js` (the newest 20 with Show earlier; a note saved while 25 notes are an hour ahead drawn after the refresh in time order; the composer keeping its text through Show earlier and a newer read; notes sharing an id each revealing their own text, found again by content after a newer read, and a deleted one selecting nothing) and `test/app.test.js` (R8 to R10: a note's draft, typing while it saves, clearing and a refused long note, as before).
- **Older copies, from their own shipped code**: `test/compat.test.js`, `test/compat-bridge.test.js` and `test/old-bundles.test.js`, with 2.10.0 now recorded as an older release.

Also on the release commit: code review: rounds pending.

## What isn't proven on real OneDrive

- A note added on one computer while the other adds notes on the same step, over real sync delays, with the new note drawn outside the newest 20.
- A follow-up's open form kept while the other computer decides or removes it over real sync delays.
- A mixed team (2.10.0 and 2.11.0) adding notes to the same run over real sync delays.

## What still runs by hand

The one-computer browser check in Edge and Chrome from a real `file://` path: Find a checklist with the keyboard and a screen reader; Show more's focus and scroll on Checklists, Runs › Follow-ups and a step's notes; a search hit on an older note, on a desktop and at phone width; a plan saved while a Runs filter is on; a long dropdown's Find box.
