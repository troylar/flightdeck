# Two-computer rehearsal waived (not rehearsed): Flightdeck 2.1.1

- Version: 2.1.1
- Date: 2026-10-23
- Decision: the project owner waived the two-computer rehearsal (docs/onedrive.md, *Release gate*) for this release.

## Why it was asked for

2.1.1 is a patch, so CONTRIBUTING.md doesn't require a rehearsal, but it changes `src/storage/` and the saving code in `src/ui/app.js`, and docs/onedrive.md says "when in doubt, rehearse". A planned run's decision is now written before its run, a run that didn't save is saved again only by Try again in the same window, and a decision file that can't be used holds its plan. No file format changes: a decision is still `flightdeck-plan-status/1`, now in `<plan>.status-<window>-d.json`, which every release from 1.10 on reads.

## What the rehearsal would have covered

The script's planned-run steps, once with both computers on 2.1.1 and once with one on 2.1.0 and one on 2.1.1:

- a plan started on one computer while the other has it open, and the decision still syncing when the other tries to start it;
- a run whose save fails (OneDrive paused) and is saved again with Try again;
- a plan edited after it was started, on each computer;
- a decision file that arrives torn, and the plan held until it reads.

## What covers it instead

Automated tests in `./test/run.sh`, all green on the release commit:

- **Older copies, from their own shipped code** (`test/compat-harness.js`, every tag from 1.10.0 to 2.1.0): every release with plans reads 2.1.1's `-d` decision as the plan's decision, and 2.1.0 refuses a second start of a plan 2.1.1 started, even before its run arrives.
- **Start once** (`test/app.test.js`, the built app with saves paused and failed at exact points): decision before run, Try again per plan, Try again refused after a person or folder change, including a start still saving.
- **Failed reads and held plans** (`test/failed-reads.test.js`, `test/folder.test.js`, `test/cli.test.js`): a decision that can't be used holds its plan on the plan page, in Folder health and in `held` for other apps.
- **The folder checker** (`test/checker.test.js`): agrees with the app on decisions, copies, file names and missing runs.
- **Two computers, simulated** (`test/sync.test.js`).

## What isn't proven on real OneDrive

- Two computers starting the same plan within seconds of each other over real sync delays (there is no shared lock across computers; documented as a known issue).
- How long a decision file takes to arrive, and that the other computer holds the plan while it is torn.
- A mixed team (2.1.0 and 2.1.1) over real sync delays.

## Known issues carried forward

See README, *Fixed in 2.1.1*, and docs/updating.md: two computers starting the same plan at the same moment can both start it, a 2.1.0 copy can still start a plan that was edited after it was started, and a renamed plan decision that can't be read holds no plan until it reads.
