# Two-computer rehearsal: Flightdeck 2.1.0 (waived)

- Version: 2.1.0
- Date: 2026-10-22
- Decision: the project owner waived the two-computer rehearsal (docs/onedrive.md, *Release gate*) for this release.

## Why it was required

2.1.0 writes new required features into existing formats (`conditions` on a version, `staged` and `test-run` on a stage and its runs), a new folder (`staged/`) with a new family (`flightdeck-stage-decision/1`), and changes `src/storage/` and the saving code in `src/ui/app.js` (a run's save compares the whole file; a plan is started, declined or switched only after its files are read again). By the rule in docs/onedrive.md, it needs the rehearsal.

## What the rehearsal would have covered

The script's steps 0 to 23, P and R, and the accounting tally, run once with both computers on 2.1.0 and once with one computer on 2.0.1 and one on 2.1 (docs/onedrive.md, *Older copies*), on a test folder holding:

- a checklist that uses nothing new (it must publish exactly as on 2.0, and both computers record on it as before);
- a checklist with `only when` on a step and on a phase (2.0.1 names it "needs Flightdeck 2.1" and starts nothing);
- a staged version with test runs on one computer, signed off and made the default on the other; 2.0.1 never lists `staged/` and shows a test run by name only;
- a planned run started on one computer while the other has the same plan open, and a plan decision file still syncing.

## What covers it instead

Automated tests in `./test/run.sh`, all green on the release commit:

- **Older copies, from their own shipped code** (`test/compat-harness.js`, every tag recorded from 1.10.0 to 2.0.1, with the floor at 1.11.1): `test/compat.test.js`, `test/compat-formats.test.js`, `test/compat-conditions.test.js` (a version with `only when` refused by name on older copies, nothing started or written), `test/compat-staging.test.js` (stages and test runs never read as versions or real runs by older copies), and `test/old-bundles.test.js` (the shipped pages of older releases, 2.0.1 included, on files this version writes).
- **File formats**: `test/envelope.test.js` (every family, the lowest sufficient format, frozen samples byte for byte; extensions stay refused).
- **Conditions**: `test/conditions.test.js` (what applies, Not needed with its reason, a skipped phase and its gate).
- **Staging and test runs**: `test/staging.test.js`, `test/staging-app.test.js`, `test/test-runs.test.js`, `test/test-runs-app.test.js`, `test/readiness-stage.test.js` and `test/readiness-stage-app.test.js` (make default publishes exactly what was staged; test runs counted only for their stage).
- **Failed reads and plans**: `test/failed-reads.test.js` and `test/app.test.js` (a file that can't be read is never taken as absent; a plan is started, declined or switched only past the write-time check).
- **Two computers, simulated**: `test/sync.test.js` and `test/app.test.js` (the built app with races paused at exact points).

## Known issues carried to 2.1.1

See docs/updating.md. *Staging and test runs (2.1)*: until they update, older copies count a test run in Home's running number and list its stage as a version in How runs go. *What to know when moving to 2.1*: the shorter fingerprint on plan decisions and edit history, and three rare ways a planned run can still start twice.

## What isn't proven on real OneDrive

- How long a stage's files take to arrive, and that the other computer shows it as still syncing until they all match.
- Two computers starting the same plan within seconds of each other over real sync delays (there is no shared lock across computers).
- A mixed team (2.0.1 and 2.1) over real sync delays.

## What still runs by hand

The one-computer browser check in Edge and Chrome from a real `file://` path: publish a checklist with `only when` and run it; stage a draft, start a test run, sign off and make it the default; start and decline a planned run.
